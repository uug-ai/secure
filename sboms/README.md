# Software Bills of Materials

This directory contains the latest SPDX document collected for `uug-ai`
repositories whose names begin with `hub`, plus the exact `factory` and `vault`
repositories. Other organization repositories are outside the inventory scope.

```text
sboms/
  index.json
  <repository>/
    README.md         # Quality score breakdown by SPDX field
    status.json
    sbom.spdx.json  # Present after a successful collection
```

`index.json` is the authoritative coverage inventory. Repository status values
are:

- `collected`: the document was refreshed in the current run.
- `stale`: refresh failed and the last successful document was retained.
- `unavailable`: no document has been collected yet.

Every target repository has a `status.json`, including repositories whose SBOM
is unavailable. This keeps coverage gaps visible in the repository tree without
publishing a misleading empty SPDX document.

Directories for repositories that no longer match the target scope are removed
by the next successful collection.

Repositories can also be explicitly excluded by the collector when retired or
when their SBOMs are no longer approved for publication. Run
`GOWORK=off go run ./cmd/collect-sboms -refresh-existing` to apply exclusions
and scoring changes to checked-in evidence without contacting GitHub.

Each collected or stale entry also contains a quality score and component
coverage metrics. The score is weighted as follows:

- Document metadata: 20%.
- Package identity, including versions and package URLs: 30%.
- Declared and concluded licenses: 20%.
- Supplier and download provenance: 15%.
- Document-to-package and other SPDX relationships: 15%.

The root README renders scores as green (85-100), yellow (70-84), orange
(50-69), or red (0-49 and unavailable). Quality measures completeness, not
whether components are secure or free of vulnerabilities. Each repository's
`README.md` breaks the score down into one row per SPDX field with coverage,
earned points, and the remaining point gap.

A document describes its subject either through `documentDescribes` or through
a `DESCRIBES` relationship from the document, which is the form GitHub emits.
A download location counts only when it is a URL or VCS location in the form
SPDX 2.3 defines, so placeholders such as a scanned directory name earn no
provenance points.

## Enrichment

GitHub's Dependency Graph leaves download locations and declared licenses as
`NOASSERTION`. During collection, the collector fills those two fields, never
replacing an asserted value or an explicit `NONE`:

- Download locations come from each package URL: the Go module proxy, or the
  GitHub repository for `uug-ai` modules, which builds fetch directly through
  `GOPRIVATE`; the npm registry tarball; the GitHub repository for actions and
  reusable workflows; and, for PyPI, the source distribution or universal
  wheel listed by the PyPI JSON API.
- Declared licenses come from [deps.dev](https://deps.dev) for Go, npm, and
  PyPI packages. A package is left unasserted when deps.dev reports a license
  it cannot map to an SPDX identifier.

Version ranges, which GitHub reports when a manifest has no lock file, do not
identify one artifact and are not enriched. Enriched documents list
`Tool: uug-ai-secure-collect-sboms` as a creator and summarize what was added
in `creationInfo.comment`. Registry lookups stop after three consecutive
failures; the affected fields stay unasserted until the next collection and the
workflow log records a warning. Supplier fields are not enriched because no
reliable source exists for them.

## Improving a score

Orange means the SPDX document is 50-69% complete under this repository's
quality rubric. It does not indicate known vulnerabilities. A repository's
breakdown page shows the current coverage and point gap for every scored field.

Version, PURL, download-location, and declared-license gaps can usually be
improved in the affected repository by committing complete supported
dependency manifests and lock files, and by adding a license file to
first-party modules. Concluded licenses require license analysis or review.
Supplier gaps are omitted by GitHub's Dependency Graph SBOM endpoint and cannot
be fixed in the affected application's source repository.

SBOMs are generated by GitHub from dependency manifests and lock files. They do
not replace image, runtime, or manually supplied component inventories where
the source dependency graph is incomplete.
